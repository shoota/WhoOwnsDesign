# 反証調査 — 統合所見A〜Hの条件付き化と「設計上のゆらぎ」

[`README.md`](./README.md) の横断統合所見A〜Hに対し、**コンセンサスのある信頼源に基づく反証**と、**設計上のゆらぎ・判断材料の変化に伴う結果の乖離**のケース調査を実施した記録。各反証は独立した妥当性検証エージェントの審査を経ている。

> ⚠️ このログ自体にも限界がある(§5)。結論を鵜呑みにせず、出典と限界の両方を読むこと。

## 1. 目的と方法

| 項目 | 内容 |
|------|------|
| 対象 | README横断統合所見 A〜H(8件) |
| 証拠基準 | ①特例的反例の排除(複数の独立した信頼源で再現的に観察される条件依存性のみ採用)②情報源の信頼性序列(Tier1=組織/事業者/標準化団体/大規模調査 > Tier2=著名実務家 > Tier3=一般個人)③コンセンサスの確認 |
| 構造 | 各所見ごとに 反証調査 → 独立した妥当性検証(特例性・序列・帰属の正確性を審査) |
| 規模 | 16エージェント / 39反証点 / 約100の出典参照 |
| 実施日 | 2026-06-07 |

## 2. 総括 — 全所見が「条件付き」に、棄却できた反証はゼロ

| 指標 | 結果 |
|------|------|
| robustness 判定 | **8件すべて `conditional`**(robust=0, contested=0) |
| 反証点の審査結果 | accept **24** / downgrade **15** / reject **0** |
| 情報源序列の遵守 | 8件すべて respected=true |

**含意**: README の統合所見は、どれも「普遍則」ではなく**すべて条件依存の推奨**だった。ユーザー指定の厳格な基準(特例排除・序列遵守)を守ってもなお、**棄却できた反証は一つもなかった**。

ただし、この「全部conditional」という結果は額面どおりに受け取るべきではない。**あらゆる一般化命題は条件付きである**(反証の非対称性)。したがって価値は「conditionalか否か」ではなく、**どの判断材料が変わると結論が反転するか**——その具体にある。以下それを抽出する。

## 3. 所見別:結論を反転させる「判断材料」と検証後の限定

| 所見 | 当初の表現 | 結論を反転させる判断材料 | 検証後の限定 |
|------|-----------|------------------------|------------|
| **A** トークンファースト | トークンがSSOTの核、コンポーネントは派生物 | スケール(マルチブランド/複数PF)・自動化インフラ・チーム規模 | 普遍則でなく「スケール要件・自動化・成熟したセマンティック設計を備える組織で最も再現性が高いモデル」。SSOTの射程は**ビジュアルプロパティに限定**(インタラクション/振る舞いは射程外)。業界の60%は手動同期=名目的SSOT |
| **B** 三層トークン | primitive→semantic→component が業界標準、primitive直参照は禁則 | テーマ/ダークモード/マルチブランド要件・設計言語の成熟度・トークン種別(色か非色か) | 「業界標準」でなく「広く採られた実務パターン」(DTCGは層数を規定せず)。要件が揃わなければ**二層が合理的代替**。直参照禁則はカラーで強いが初期段階・非カラーでは許容実態あり |
| **C** 文書5層構造 | Foundations/Components/Patterns/Content/Resources が標準 | コンテンツ専任者の有無・対象ユーザー・主ツール(Storybook主体か) | 「標準」でなく「上位実践モデル」。**Content層採用13〜45%、Patterns層も6割が不採用**。GOV.UKはFoundations/Resourcesなし。Storybook主体では5層が成立しない |
| **D** even over原則 | 良い原則はトレードオフを明示すべき | トレードオフが実在するか・原則の目的が決定支援か・両者を同時最大化できるか | 「必要条件」でなく「トレードオフが実在し決定支援が目的の成熟組織に有効な一選択肢」。USWDS/Carbon等は**aspirational形式でも整合を達成**。「Accessibility even over Aesthetics」は偽の二項対立になりうる |
| **E** Web制約の機械検証 | WCAG/CWV/状態をAI・CIが自己検証できる具体値に | 検証対象が構文・構造レベルか、意味・文脈レベルか | 「構文・構造レベルの一部」に限定。alt**存在**・単色背景コントラスト・reduced-motion・ラボLCPは可。alt**等価性**・フォーカス順序の妥当性・動的CLS/INP・WCAG3.0定性項目は**自動検証不可**、専門家手動が不可欠 |
| **F** Hybridガバナンス | 高採用の68%がHybrid、所有明確化が運用可能性に直結 | プロダクト数・成熟フェーズ・エグゼクティブ支援/貢献インセンティブの有無 | **「68%」はTier1で裏付けられず**(Sparkbox 2022=ガバナンス保有44%と不整合)→根拠提示すべきでない。所有明確化は**必要条件だが十分条件でない**(DX・文化的投資に同程度依存)。「直結」は過大 |
| **G** AI二層ドキュメント | 人間向け散文+AI向け構造化データの二層が有効 | 組織成熟度・自動化の有無・ツールと目的 | 方向性は支持。ただし**手動管理下では「散文/構造化/コード」の三者ドリフトを新たに生むリスク**。llms.txtは主要LLMの正式対応なく投機的。最適形態は目的依存。未成熟組織には段階導入が現実的 |
| **H** 失敗は文化・運用 | 失敗の主因は技術でなく文化・運用 | 組織規模・プラットフォーム数・成熟フェーズ | 中〜大規模では成立。ただし**「技術は常に副因」は過大**——Sparkbox 2022は技術的負債43%・採用36%が**ほぼ同率**。技術基盤の誤りは文化的解決では回収できない構造的負債を生む |

## 4. 横断する本質 — デザインシステムは「判断の凍結」、判断材料が動けばドリフトする

8所見の反転トリガーを並べると、一本の縦串が見える:

> **スケール / 成熟度 / ブランド要件 / プラットフォーム数 / チーム規模 / 自動化の有無** ——これらの「判断材料」が変わると、A〜Hの最適解はことごとく反転する。

デザインシステム・トークン・原則・文書構造は、いずれも**「ある時点・ある文脈で下した判断の凍結」**である。判断材料は常に動くため、凍結された判断は文脈が動いた瞬間から最適解より乖離し始める——これが**ドリフト**。つまりA〜Hは「正しく作る」問題ではなく、本質的に**「陳腐化に抗い続ける」問題**である。

この視点は、本リポジトリの設計に直接効く:現状のIssue #1の論点はすべて「**何を用意するか(what to provide)**」に閉じているが、実運用を分けるのは「**用意したものが判断材料の変化でドリフトしたとき、どう検知し・更新し・いつ意図的に逸脱(override)を許すか**」である(§6)。

## 5. この反証調査自体の限界(メタ)

このログを過信しないために、構造的限界を明示する。

**(a) 同質モデルによる検証 — 実際に自己矛盾が出た**
反証調査も妥当性検証も同じモデル族(Claude/sonnet)。前ターンで予告した「同質性の盲点」が**実際に発現した**:所見Aの反証で、**Tier1出典の誤帰属が複数検出**された——
- `goodpractices.design` からの引用「tokens lack crucial information about the decisions…」が**実際の記事に存在しない**(検証者がフェッチで確認)
- DTCG FAQが「インタラクション・振る舞いはスコープ外」と**明示している事実が確認できなかった**

**出典の厳格化を掲げた調査が、出典を誤って引用した**。これは方法の自己反証であり、Web調査ベースである限り避けられない確度限界を示す。

**(b) Tier1の利益相反 — 信頼性 ≠ 中立性**
採用した組織源(zeroheight・Sparkbox・NN/g・Figma)は、いずれも**デザインシステムの価値を語ることに利害を持つ当事者**である。再現性・体系性は高い(=信頼できる)が、中立ではない。最もポジショントークの動機がある層を、最も信頼できる層として扱う逆説が残る。

**(c) コンセンサス基準のパラダイム内限界**
「特例排除+コンセンサス重視」は、パラダイム**内**の揺らぎ(条件依存)は捉えるが、パラダイム**そのもの**への疑問——「そもそもデザインシステムという枠組みが特定文脈の産物では?」——は構造的に検出できない。業界が共有する集合的前提は、この方法では不可視。

**(d) 反証の非対称性**
§2のとおり、conditional多発は部分的に予定調和。本当に効くのは「条件の中身」であって判定ラベルではない。

**(e) 数値の脆さ**
「68%」(F)・「自動化チームの信頼+11%」(A)・「500 component token」(B)など、複数の定量値が一次で裏付けられなかった。**README統合所見Fの『68%』は本調査で根拠を失った**ため、要修正。

## 6. Issue #1 への示唆(新論点の提案)

反証調査の最大の収穫は、個別の限定よりも**論点の不足の発見**である。

- **新論点9:デザインからの「逸脱・例外」とドリフトのガバナンス**
  AIは凍結ルールに**忠実すぎる**。人間は「この文脈ではトークンを破るべき」と判断できるが、AIは破る根拠を持たない。「**いつルールを破ってよいか / ドリフトをどう検知し更新するか**」をAI(とチーム)にどう与えるか——これは現状の論点に無い空白。

- **新論点10:定義に付すべき「条件メタデータ」**
  本調査が示すとおり、あらゆる指針は条件依存である。各定義(トークン・原則・制約)に **`適用条件 / スケール前提 / 確信度 / 最終検証日 / 反転トリガー`** を構造化メタデータとして付す。これにより、AIは確信度の低い・条件外の記述を構築判断の根拠にする前にフラグを立てられる。既存のどのデザインシステムも明示していない空白であり、**本リポジトリの独自価値になりうる**。

- **既存論点への補正:単一の正解集ではなく「条件分岐する処方箋」**
  「何を用意するか」の答えは、組織の**規模・成熟度・要件**で分岐する。本リポジトリは「唯一の正解」ではなく、**条件で分岐する処方箋**として設計すべき(例:小規模単一プロダクト向けの最小セット ↔ マルチブランド大規模向けのフルセット)。
